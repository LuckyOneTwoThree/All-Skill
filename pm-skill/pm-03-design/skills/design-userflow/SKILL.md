# Pipeline 10: 用户流程自动设计

## 核心原则

1. **批量生成人类筛选**：AI批量生成分类/排序建议，人类做最终筛选和判定
2. **结构化发散**：用固定模板和框架引导需求拆解，避免遗漏和随意性
3. **假设驱动而非功能驱动**：每个需求背后必须还原为用户假设，而非直接进入功能设计
4. **设计规范即约束**：需求分析阶段就引入设计规范约束，避免后期返工

🤖→👤 AI建议 → 人类审批

## 交互模式

🤖→👤 AI建议人类审批

## 输入

| 输入项 | 类型 | 必填 | 来源 | 说明 |
|--------|------|------|------|------|
| PRD | markdown | 是 | design-prd → prd.md | 产品需求文档 |
| IA方案 | JSON | 是 | design-ia → ia.json | Pipeline 9输出的信息架构方案 |
| 用户研究数据 | JSON | ○ | user-research-voice-analysis / user-research-behavior-analysis | 用户行为模式、任务偏好 |

## 执行步骤

### Step 1: Task Flow生成

定义任务级流程：

- **起始点**: 用户进入场景
- **步骤序列**: 完成任务的核心路径
- **系统响应**: 每步的系统反馈
- **终止点**: 任务完成状态

### Step 2: User Flow生成

扩展为完整用户流程：

- **条件分支**: if/else决策节点
- **异常路径**: 网络错误、无权限、空状态等
- **返回路径**: 返回上一步的操作
- **替代路径**: 完成同一目标的不同方式

### Step 3: 流程质量自动检查

对生成的流程进行质量验证：

| 检查项 | 说明 |
|--------|------|
| 最短路径 | 核心任务最少步骤数 |
| 异常覆盖 | 异常路径覆盖率 |
| 返回路径 | 是否支持返回操作 |
| 决策点信息 | 决策时信息是否充分 |
| 死胡同 | 无法完成任务的情况 |

### Step 4: 流程优化建议

基于质量检查结果提出改进：

- **过长路径标注**: 步骤>5的路径标记
- **异常处理补充**: 未覆盖的异常场景建议
- **引导建议**: 复杂节点的引导优化
- **死胡同处理**: 消除或优化死胡同

## 决策规则

- **死胡同数量必须为0** - 任何死胡同都需要修复
- **质量检查必须通过**才能进入原型阶段
- 核心任务路径步骤数<5为最佳

## 质量检查

- ✅ 核心任务步骤数 < 5步
- ✅ 异常路径覆盖率 ≥ 80%
- ✅ 死胡同数量 = 0
- ✅ 所有决策点信息充分
- ✅ 返回路径完整

## 降级策略

当上游文件不存在时，本Skill仍可独立执行：

| 缺失的上游文件 | 降级方案 |
|---------------|---------|
| PRD文档 | 用户提供功能描述 → 直接设计流程，标注"缺乏PRD结构化数据" |
| ia.json（IA方案） | 用户提供功能描述 → 直接设计流程，标注"缺乏IA数据" |
| PRD + IA方案 | 用户提供功能描述 → 直接设计流程，整体置信度降低 |
| 所有上游文件均缺失 | 提示用户先执行前序阶段，或基于用户提供的功能描述直接设计流程 |

数据获取说明：
- 本Skill需要PRD和IA方案数据，请通过以下方式之一提供：
  1. 直接描述功能流程和用户任务
  2. 上传PRD文档 / ia.json文件
  3. 提供数据文件路径
- AI不负责外部数据采集，仅负责分析
