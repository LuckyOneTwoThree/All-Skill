# 用户留存指挥官

## 核心原则

**留存是衡量产品价值的核心指标**

获客决定起点，留存决定终点。如果用户不愿留下，说明产品尚未交付足够的价值。留存问题的根因永远是价值问题，而非运营问题。

## 执行步骤

1. **千人千面**：不同生命周期阶段、不同流失风险等级的用户采用差异化留存策略
2. **自动实验持续优化**：干预策略通过A/B测试验证效果，持续迭代策略库
3. **实时优化**：流失预警模型实时运行，高风险用户即时触发干预
4. **数据驱动归因**：量化每个干预策略的留存提升效果，明确策略ROI

## 任务调度

```
retention-churn → retention-engagement
```

### 调度逻辑

| 触发事件 | 调度动作 |
|----------|----------|
| 每日执行 / 用户行为数据更新 | → retention-churn（流失预警） |
| 流失预警完成 / 生命周期阶段变化 | → retention-engagement（分层运营） |
| 运营日历触发 | → retention-engagement（策略执行） |

### 数据流转

```
[用户行为数据 + 流失模型]
       ↓
retention-churn
       ↓ churn_prevention (risk_model / high_risk_users / interventions / tracking)
retention-engagement
       ↓ user_stratification (segments / strategies / personalized_content)
```

## 调度规则

- 每次只加载当前阶段需要的子Skill，完成后再加载下一阶段，不要一次性加载所有子Skill
- 每个阶段完成后，将中间结果写入 `output/pm-growth/{skill-name}/` 文件，释放上下文空间
- 若上下文接近上限，优先保留当前阶段内容，将已完成阶段的输出摘要为关键结论
- 单个子Skill的输出应控制在2000字以内，超出部分写入文件

## 阶段卡口

| 卡口 | 通过条件 | 未通过处理 |
|------|----------|------------|
| 流失预警模型已构建 | 流失预警模型运行正常，高风险用户已识别 | 优化模型或补充训练数据 |
| 用户分层已完成 | 全量用户已完成生命周期分层，各层策略已生成 | 补充分层维度或延长分析周期 |

## 人类决策点

| 决策点 | 触发条件 | 决策内容 |
|--------|----------|----------|
| 干预策略确认 | 流失预警和分层运营策略生成完成 | 确认干预策略的优先级、触达方式和资源分配 |
